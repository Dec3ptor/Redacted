What is actually in the file

A reversible file is the flattened redaction everyone can see, plus one encrypted block that holds the exact bytes of the original document. The block is sealed with AES-256-GCM. The key never travels with the file, is never stored by this site, and is never sent anywhere.

Without the key that block is indistinguishable from noise, and the visible page is a picture — the covered words are not in the text layer any more than they are in a permanent redaction. With the key, the original comes back byte for byte.

When to use reversible, and when not to

Reversible is for a file you still control: a draft going round your own team, a copy held for a case where a court may later order the original produced, a document you may need to re-redact differently. The value is that one file serves both purposes and the original cannot drift out of sync with it.

It is not the mode for the final copy you hand to the other side. The original travels inside the file, so anyone who ends up with both the file and the key has everything, and a file already sent cannot be recalled. Redact permanently for that, or use Make permanent here to strip the recovery block before the file goes out.

The honest summary: reversible trades a smaller blast radius for a recoverable one. That trade is worth making inside your own boundary and worth refusing outside it.

If the key is lost

There is no recovery, no reset, and no back door — that is the point of the design, and it is what makes the encrypted block safe to ship inside a document. Keep the key somewhere separate from the file itself. How it works has the full account.
